# Решения

Что решили и почему. Новые записи — сверху.

## 16.09.2026 — S3 «Редактор, панель на Preact + Vite, монохром»

- **Vite живёт внутри `studio/server.ts`, а не отдельным портом с прокси.** В dev сервер создаёт Vite в режиме middleware на том же http-сервере 5177: API, WebSocket `/api/events`, `/files/` и страница — один процесс, один Host, заголовок `X-Hygen` и проверка Origin работают без прокси. HMR Vite подключён к тому же серверу, обработчик upgrade живого канала пропускает сокеты с протоколом `vite-hmr`. Prod — `npm run studio:build` → `studio/dist/` (в `.gitignore`), `npm run studio:dist` отдаёт собранное без Vite. `npm run studio` всегда dev: собранный `dist/` не подменяет свежий код молча.
- **Страница — Preact 10 + @preact/signals, TSX в `studio/web/src`.** Живой канал и список идущих диалогов — сигналы; экраны грузят данные `useApi` (первая загрузка — «загрузка», `reload()` тихо заменяет данные — Preact сверяет разницу, открытые карточки и прокрутка остаются). Ручной `h()` и `dom-shim` удалены. xterm остаётся императивным островком: один терминал на вкладку, его узел переносится в панель открытого проекта.
- **Смоук-тест рендерит форму тем же `forms.tsx`, что и страница:** `studio/check.ts` поднимает Vite в режиме SSR (`ssrLoadModule`) и отдаёт поле `preact-render-to-string`. Шестая строка проверки — «создание из брифа»: проект открывается в настоящем браузере, бюджет в `project.json`, задач, диалогов и `build/` нет, страница не отправила ни одного запроса на запись.
- **Отфильтрованная карточка галереи прячется `display:none`, а не выходит из списка.** Иначе Preact размонтирует узел и загруженное превью грузится заново — ровно то, что чинил S2.1.
- **«Создать» пишет проект целиком, а не один бриф.** `POST /api/brief` кладёт `brief.json`, скелет `project.json` (статус `brief`, Kokoro, `voice.budgetChars` из обязательного поля формы, `beats: []`, look из брифа или конфига) и пустой `media.json` — и больше ничего. `loadSpec` пускает пустые биты и не требует `sound` у проекта без битов; `build` и `verify` отказывают словами «нет битов — это пока бриф». Бриф с битами считается черновиком (`statusOf`). Контекст диалога проекта без битов начинается строкой `/short <id>`.
- **Любой идущий диалог завершается откуда угодно:** в сайдбаре — строка на каждый живой диалог (ссылка на его «Диалоги» и «Завершить» с подтверждением), в «Режиссёре» — тот же список. «Продолжить» в терминале продолжает последний диалог (`--resume`), рядом — «Новый диалог».
- **Монохром.** Токены `:root`: фон и панели — чёрный и графит, текст — белый и серые, `--accent` белый. Цвет — только у смысла: `--err` приглушённый красный, `--warn` приглушённый жёлтый. «Идёт» (сборка, диалог) — белая пульсация. Статусы — серые пилюли, `published` — белая заливка, `brief` — пунктир. Без градиентов, теней и свечений (штриховка паузы в редакторе — узор, не свечение).
- **Скраббинг по композиции — своя страница-обёртка и `__player.renderSeek(t)`, без `<hyperframes-player>`.** `GET /api/projects/:id/composition` отдаёт `build/index.html` с `<base href>` на `build/`, заглушённым звуком и рантаймом HyperFrames из `node_modules` (`GET /api/hyperframes/runtime.js`, только этот файл). Страница на том же origin, поэтому панель зовёт API рантайма напрямую; `renderSeek` — тот же вызов, которым рендерер ставит кадр (дочерние таймлайны и медиа). Кадр готов через rAF → `seeked` у видео → rAF; частые seek склеиваются — применяется последнее время. Замер на Помпеях: 30 seek — среднее 27 мс, медиана 24, максимум 52; перетаскивание 120 вызовов → 33 кадра, последний через 61 мс.
- **Карта ролика — `build/timeline.json`, её вход — `build/timing.json`.** Сборка пишет голос (границы речи, кэш), слова, моменты устройств и сетку музыки в `timing.json`, из него — карту: биты, слова, субтитры, устройства, переходы, музыка. Карта актуальна, пока sha1 `project.json` совпадает с `source.projectHash`; иначе `readTimeline` перепроецирует прошлую сборку (реальные слова неизменённых битов остаются, изменённое оценивается) или, без сборки, оценивает всё по символам. Проект без битов — пустая карта, не ошибка.
- **Пауза после реплики — существующий `pad[1]`, отдельного `hold` в схеме нет;** сдвиг музыки — ссылка на время `music.in`. Слова карты несут `ref`/`refEnd` — готовое значение `at` устройства: токен из нескольких произносимых слов ссылается на первое, конец — на `.end` последнего.
- **Оценка длины реплики — `voice.charsPerSecond` в `hygen.config.json`: Kokoro 14,4, ElevenLabs 16,8** (по кэшам 6 и 41 реплики недели 1; соотношение 0,855 сходится с «ElevenLabs короче на ~4 с»). `/short` v3.5 считает длину реплик по финальному голосу — ElevenLabs: черновик на Kokoro выходит на 15–17 % длиннее, резать его не надо.
- **`history/*/snapshot.json` пишет `machine`** (host, hyperframes, модель и коммит whisper, модель и пакет kokoro) — только из файлов, без сети. Это заметка, не вход: в отпечаток и сравнение «вход изменился» не входит, старые снимки не переписываются.
- **Журнал диалога — экранный текст** (`studio/log-screen.ts`): строка уходит в журнал, когда покидает экран терминала; дубли, одиночные значки спиннера и перевывод после очистки экрана выпадают. На синтетическом потоке перерисовок Ink: 86 строк → 9.
- **`text.kinetic` `behind-subject`: слово не короче фигуры.** Если несколько слов не выходят крайними буквами из-за фигуры ни при каком кегле, текст встаёт двумя строками по сторонам фигуры (кегль ≥ 72 px); одно короткое слово — предупреждение сборки (ширина фигуры известна только там — из вырезки `media_stage.py extent`).
- **Правки редактора идут через существующий API** (`PUT …/beats/:beat`, для музыки — `PUT …/project`): граница бита — `pad[1]` (пауза после реплики, 0–3 с, шаг 0,05), маркер устройства — `at` по пути `atField` из карты, снап к началу ближайшего слова своего бита (пишется ссылка на слово, не секунды — правило 4), музыка — `music.in = "<первый бит>:start+X"` со снапом к доле 60/BPM. Отмена — стек из 50 правок в памяти экрана, каждая хранит бит или проект до и после. Метка «изменено, пересоберите» — `card.changed`: отпечаток `project.json` не совпадает с `source.projectHash` карты последней сборки.

## 15.09.2026 — S2 «правила хранения и сборки, черновик и финал, режиссёр в диалоге»

- **Панель обновляется точечно, а не перерисовкой экрана.** Готовое превью встаёт в свою карточку (лёгкая выборка `/api/library/ready`), карточка проекта меняет только те строки, которые изменились, вид задачи перерисовывает лишь изменившиеся этапы и дописывает строки лога. Карточки живут, пока жив экран: фильтр и поиск переставляют готовые узлы, поэтому загруженные превью не теряются, чипы разделов не прыгают и прокрутка стоит на месте. Замер: за 35 секунд сборки — 2 правки DOM вместо полной перерисовки каждую секунду.
- **Видео-превью грузятся, только когда их видно** (`lazyVideo`, IntersectionObserver с запасом 300 px): в разделе субтитров при открытии грузится 8 роликов из 20 вместо всех. Ползунки обрезки видео в «Ассетах» (две копии файла с `preload: auto`) строятся только при раскрытии раздела.
- **Слежение за файлами не видит `renders/`.** О результате сборки говорит её задача; иначе каждая запись в `renders/` и `publish/` дёргала бы экран проекта всю сборку. Экран проекта перечитывается только на `project.json`, `media.json`, `media/`, `brief.json`, `research.md` — и не перечитывается, пока идёт сборка.

- **Чистая пересборка не трогает дерево.** Контактный лист и обложка сохраняются без даты и метаданных времени и не перезаписываются, если показывают то же самое, что уже лежит на диске. Сравнение — не побайтовое и не попиксельное: два рендера одной сборки расходятся на 1,4 из 255 по всему кадру (четыре воркера Chrome плюс два прохода H.264), поэтому берутся те же пороги, которыми движок всегда говорил «кадры не изменились» — среднее размытой разницы ≤ 3 из 255 и блок 60 px ≤ 40 (`same_picture` в `verify_mp4.py`, `engine/py/same_picture.py` для обложки). Текстовые файлы `publish/` пишутся через `writeIfChanged` и сравниваются по байтам. Строка `library/index.json` переписывается только при изменении отпечатка, ключи отсортированы, дата — дата изменения отпечатка, а не сборки.
- **Снимок в `history/` — по входу сборки, а не по одному project.json.** Вход: `project.json`, `media.json`, хэши файлов `media/`, список дублей `voice/` и коммит движка (`git rev-parse --short HEAD`). Причина пишется человеческим языком в `snapshot.json → why` («изменился project.json», «движок abc123 → def456») и видна во вкладке «История». Снимки, сделанные до S2, знают только свой digest — для них движок сравнивает по-старому и лишнего снимка не делает.
- **Бюджет ElevenLabs — у ролика, а не у движка.** `project.json → voice.budgetChars` (умолчание — `voice.defaultBudgetChars` в `hygen.config.json`), расход — по `projects/<id>/voice/usage.jsonl` этого ролика. Глобальный `ELEVENLABS_BUDGET_CHARS` и `budgets.elevenlabsChars` убраны, сброса бюджета больше нет: кэшированный дубль ничего не стоит, а новый ролик начинает со своим бюджетом.
- **Провайдер голоса по умолчанию — всегда Kokoro.** `voice.provider` из `hygen.config.json` и `VOICE_PROVIDER` из `.env` убраны: черновик, `/short`, «Собрать», «Без рендера» и правки битов бесплатны по определению. ElevenLabs включает кнопка «Финал на ElevenLabs» — она пишет провайдера в `project.json`, переозвучивает недостающие реплики и пересобирает ролик; «Обратно на Kokoro» возвращает правки на бесплатный голос, дубли остаются в `voice/`.
- **Статусы ролика: `draft-kokoro`, `final-elevenlabs`, `published`, `waiting-library`.** Старые `draft`/`built`/`verified` схлопнуты в `draft-kokoro` (ролики на ElevenLabs — в `final-elevenlabs`). «Собран» — это не статус, а наличие MP4 на этой машине: рендеров в git нет, поэтому карточка честно говорит «не собран на этой машине» и даёт кнопку. Само ничего не собирается.
- **Режиссёр работает только в своей папке.** Навык `/short` v3.4 не читает `projects/*` кроме своего; что занято — `library/index.json` (арка, последовательность stage, look, пресет субтитров, первые три устройства, дата отпечатка), примеры битов и скелет `project.json` — в `library/scenes/CONTRACT.md`, раздел «Примеры битов». Библиотека и документы движка читаются свободно. В живом диалоге разрешены до трёх уточняющих вопросов.
- **Бриф с жанром вместо брифа с голосом.** `brief.json`: тема, id, жанр (история, наука, факты и списки, развлекательное, объясняющее), look или «пусть решит», длина, пожелания; необязательные — арка, чего избегать, обязательный кадр. Жанр выбирает правила исследования в навыке. Поля голоса нет.
- **Автономный `claude -p` из панели убран, режиссёр — живой диалог.** Один диалог на проект, не больше двух на панель (`studio.maxDialogs`), контекст проекта первой строкой, журнал — `projects/<id>/dialogs/<дата>.log`, продолжение — `claude --resume` по id сессии. Очередь без участия человека остаётся возможной через `claude -p` и будет отдельной сессией; allowlist, «Проверить claude -p» и журнал `director.log` из панели убраны (старые `director.log` остаются в git как история).
- **Живая панель: chokidar + WebSocket.** Один канал `/api/events` несёт вывод диалога, прогресс задач и события файлов `projects/` и `library/`, склеенные по 500 мс; перечитываются только затронутые карточки. Задачи сборки переживают перезапуск сервера (`.cache/studio/jobs.json`): задача, которая шла в момент падения, читается как «прервана перезапуском», а не как идущая.
- **Регрессия удалена по решению пользователя.** Проверка движка — `npm run studio:check` (смоук-тест панели) плюс зелёный `npm run library:previews`; приёмка ролика — по кадрам его MP4. Ушли команда, её скрипт в `engine/src/`, семь снимков и кэш сравнения; индекс отпечатков переехал в `library/index.json`. Вернуть можно из истории git (коммит `b2156de`).

## 15.09.2026 — S1.1 «доводка панели, библиотека в library/, регрессия, терминал»

- **Регрессия по всем роликам вместо одного образцового.** команда регрессии (удалена в S2) пересобирала каждый не-proof проект со сборкой (черновик без MP4 пропускался — `pompeii-copy-en`) и сравнивала лист MP4 со снимком ролика порогом `compare_frames.py` (среднее ≤ 3, блок ≤ 40); `--record` писал снимки и `index.json` (HEAD, биты, длительность, голос). Помпеи — обычный проект, один из семи. Намеренное расхождение — `--record --only <id>` и запись здесь, случайное — TRAPS.
- **Среднее плитки — по размытым 3×3 плиткам, блок — по сырой разнице.** Первая регрессия после переноса дала 6 из 7: у molasses плитка r2c4 (04-wave, film-memory по светлому фото) 3,10 при пороге 3,0, блок 5,1 — ровный пиксельный шум зерна, та же плитка между листом S1 и снимком до переноса — 3,09; значит, это не перенос. Порог не поднимали: после размытия шум всех семи роликов ≤ 1,17, а сдвиг на 4 px даёт 14,0 и оттенок +8 — 8,0. Готовые листы пересчитаны без пересборки — 7 из 7.
- **Голос регрессии — только из кэша проекта** (`HYGEN_VOICE_CACHE_ONLY=1`): реплика без дубля ElevenLabs идёт на Kokoro, символы не тратятся. Поэтому снимок odyssey-en смешанный (3 реплики ElevenLabs, 4 Kokoro): сценарий правлен после озвучки, нужно 373 символа при остатке 59.
- **Всё, из чего собирается ролик, — в `library/`, в `engine/` — только код.** Перенесены looks, textures, devices (с vendor/ и VENDOR.md), transitions, arcs, intents, scenes (HTML-сцены, recipes/, CONTRACT.md, schema.json, `_runtime/`) и сверх списка промпта styles, assets (шрифты, карты, GSAP) и motion — иначе в engine/ остались бы данные. Рантайм раздела (`devices/runtime.js`, `text.js`, `motion/runtime.js`, `scenes/_runtime`) едет с разделом, `engine/stage/runtime.js` — рантайм движка, остался. Пресеты субтитров и `families.json` — `library/captions/`, устройство `text.caption` — в `library/devices/`. `engine/captions/word-by-word.html` (скин D1, не используется с D6) удалён. Корень — `LIBRARY_DIR` из `hygen.config.json → paths.library`. Решение S1 «looks, текстуры, устройства, переходы остаются в engine/» отменено.
- **trim из media.json — умолчание in/out бита, поле за полем:** бит без `in` берёт `trim.in`, без `out` — `trim.out`, явное значение бита сильнее. Проверено на копии Titanic: у 01-film убраны in/out, trim 3–9 с → клип хроники 6,0 с вместо 11 с.
- **`sampleLine` у look** — реплика превью мира: ember «18 hours», abyss «2:40 hours», storm «4,800 km», bright-explainer «Why is the sky blue?». Число с единицей считает counter-title (int, thousands или clock) с текстурами мира, другая строка печатается на карточке вопроса. Look в панели — только отдельный экран; раздела Looks в Библиотеке нет, в каталоге превью он остался.
- **Уникальность не сравнивает с несобранным черновиком:** копия из панели (draft без build.json) делала красной автопроверку оригинала — Помпеи против `pompeii-copy-en`.
- **Журнал режиссёра — `projects/<id>/director.log`:** JSON-строки `claude -p --output-format stream-json` как пришли плюс события `hygen` (start с allowlist, denied, end). Панель собирает журнал из него и файлов проекта: brief.json, research.md (Concept, Media), arc и биты project.json, лицензии media.json, voice/usage.jsonl, грамматика — живой проверкой; токены — по id сообщения. Без director.log — «сделан вручную». У Molasses и Odyssey журналы восстановлены из транскриптов Claude Code: прогоны были раньше director.log; результаты инструментов обрезаны до 1 000 символов, стоимости в транскрипте нет.
- **`claude -p` из панели — allowlist:** `--permission-mode dontAsk --setting-sources project --strict-mcp-config --allowedTools "Bash(npm run *)" "Read(./**)" Glob Grep "Write(./projects/<id>/**)" "Edit(./projects/<id>/**)" "WebFetch(domain:en.wikipedia.org)" TodoWrite`. WebFetch к Wikipedia — сверх списка промпта: навык исследует тему по Wikipedia, его `curl` теперь отказан, без чтения Wikipedia research.md не собрать. Отказ пишется событием по тексту ответа инструмента и по `permission_denials`. Проверка (`sessions/2026-09-15_1541_S1.1_allowlist-check.log`): чтение CLAUDE.md, запись в проект и `npm run scenes` разрешены; запись в корень, `ls /` и чтение /etc/hostname отказаны.
- **Терминал — node-pty в сервере и xterm.js в странице через SSE и POST, без WebSocket:** зависимостей две, протокол простой. Один `bash -l` на панель в корне репозитория, буфер 400 КБ повторяется при переподключении — вкладку можно закрыть. ## 14.09.2026, день — D4 «визуальный язык: stage + devices + intent»

- **Бит v2 = stage + 0–3 устройства, сцены с HTML остаются рецептами.** Бит — либо `scene`, либо `stage`; семь сцен Помпей не тронуты (сборка Помпей без рендера после всех правок — все артефакты build/ побайтно как у образца). Разметка stage (клипы видео, стоп-кадры, пути карты) статичная, анимации — `HygenStage.mount` и `HygenDevices.mount` на одном paused-таймлайне; видео внутри подкомпозиции HyperFrames находит и сдвигает сам.
- **Устройство — модуль `define(type, mount)` + `device.json`, слои z фиксированы (stage → focus → data → annotate → text).** Модули собираются в `assets/hygen/devices.js`, отдельный файл от `runtime.js` motion: повторная загрузка в шаблоне кадра не должна сбрасывать состояние камеры.
- **Видео — полноценное медиа через подготовку при сборке.** `in`/`out`, reverse и treatment запекаются ffmpeg в H.264 в кэш по хэшу; в рендере — `data-media-start`, `data-playback-rate`; стоп-кадр — точный кадр ffmpeg как `<img>`-клип между двумя видеоклипами, источник продолжается с того же кадра. `fit: contain` — полоса на размытом фоне из того же кадра (архивное 4:3 в 9:16 без апскейла ×5).
- **Обработки media-use (film-memory, engraved, two-ink) — CPU-версии, не шейдерные payload'ы.** Картинки — numpy (штриховка, растры 15°/75°), видео — тоновые карты ffmpeg; движение film-memory (gate weave, дыхание экспозиции) — твинами. Шейдерный путь HyperFrames тянет WebGL и рендер в 1 поток.
- **Компоненты реестра вендорятся и портируются, а не вставляются.** hw-* пишут boil и squash через `tl.eventCallback("onUpdate")` — застывают при перемотке (TRAPS.md). Исходники и sha256 — `engine/devices/vendor/` и `VENDOR.md`; порт живёт в `device.js` на токенах look и шрифтах стиля (Caveat не вендорен).
- **Intent и JSON-рецепт — одна таблица подстановок.** `$target`, `$at±s`, `$data.key|default`, условное устройство `"if"`; явные поля бита побеждают. Резолвер детерминирован по построению (чистая функция video.json и таблиц), проверяется двумя развёртками в одном запуске и хэшем входа против прошлой сборки (`beats.expanded.json`, проверка `expanded` в verify).
- **Координаты устройств — проценты кадра, моменты — слова.** Параметр типа `at` (например, `fillAt` у annotate.box) тоже слово: секунды внутри устройства пришлось бы подбирать под каждый голос.
- **Камера stage-бита двигается только с reason** (approach → push-in, reveal → pull-out, follow → pan, tension → handheld). Look задаёт камеру сценам; stage-бит без reason стоит — у медиа-доказательства камера не должна плыть без смысла.
- **Уникальность скелета — против двух последних роликов по времени сборки,** цвет и текстуры D3.5 — против всех. Пересказ в том же мире объявляется `"retells": "<id>"` и освобождается от проверки цвета только в паре с оригиналом; арка и последовательность stage проверяются всегда.
- **Грамматика — в build до голоса и в verify.** Ошибки останавливают сборку за секунды, а не после 3-минутного рендера; ритм — предупреждения, режиссёр читает их сам.

- **Структура:** репозиторий — папка `hygen`. `engine/` — основной движок, `videos/` — ролики, `examples/pompeii-short` — образец, только читать.
- **Приёмка без гейтов:** итоговый MP4, кадры, «что видно», автопроверка.
- **Голос:** Kokoro на черновики, ElevenLabs на финалы. Финальные дубли хранятся файлами.
- **Субтитры:** HTML-композиция с пресетами (слово за словом, поп-слова, караоке, минимал), SRT всегда.
- **Звук:** динамику генерируем кодом по таймингам сцен, музыку берём из библиотеки с лицензией.
- **Медиа:** только источники с лицензией, на каждый файл — запись о лицензии.
- **Уникальность роликов:** стиль-пак, одна геройская сцена на ролик, вариации параметров.
- **Docker — позже,** когда рендер переедет на сервер или машин станет несколько.
